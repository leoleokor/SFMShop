+# Git Workflow для проекта SFMShop
+
+## Использованные команды Git
+
+* `git init` - инициализация репозитория
+* `git add` - добавление файлов в staging area
+* `git commit -m` - создание коммита с сообщением
+* `git status` - проверка состояния репозитория
+* `git log --oneline` - просмотр краткой истории коммитов
+* `git log --oneline --graph --all` - просмотр истории с графом веток
+* `git branch` - просмотр списка веток
+* `git checkout` - переключение между ветками
+* `git checkout -b` - создание новой ветки
+* `git merge` - слияние веток
+* `git rebase` - обновление ветки поверх master
+* `git stash` - временное сохранение изменений
+* `git diff` - сравнение изменений между ветками
+* `git show` - просмотр конкретного коммита
+* `git push` - отправка изменений на GitHub
+* `git pull` - получение изменений из удалённого репозитория
+
+## Созданные ветки
+
+* `master` - основная ветка проекта
+* `feature/add-discount-system` - ветка для системы скидок
+* `feature/add-email-validation` - ветка для валидации email
+* `feature/add-inventory-management` - ветка для управления складом
+* `feature/test-conflict` - ветка для практики конфликтов
+* `feature/test-rebase` - ветка для практики rebase
+* `feature/add-shipping` - ветка для расчета доставки
+* `feature/add-logging` - ветка для системы логирования
+* `feature/add-caching` - ветка для системы кэширования
+
+## Разрешенные конфликты
+
+* Конфликт в `src/models/product.py` при слиянии `feature/test-conflict`
+* Конфликт был разрешен вручную через редактирование файла
+* После разрешения выполнен `git add` и создан merge commit
+* Также был разрешен конфликт при слиянии ветки `feature/add-shipping`
+
+## Организация workflow
+
+Для каждой новой задачи создавалась отдельная feature-ветка.
+Изменения добавлялись через `git add`, после чего создавались коммиты с понятными сообщениями.
+После завершения работы ветка отправлялась на GitHub и создавался Pull Request.
+Для обновления feature-веток использовались `merge` и `rebase`.
+
+## Стратегия работы с ветками
+
+* Основная работа ведется в ветке `master`
+* Для каждой новой функции создается отдельная ветка `feature/...`
+* Каждая ветка содержит отдельную задачу
+* Перед merge проверяются конфликты и история коммитов
+* После завершения работы изменения отправляются на GitHub через Pull Request
